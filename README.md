# VTOP Modern

VTOP Modern is a local-only Manifest V3 browser extension for VIT student
portal pages. It adds typed attendance planning, best-effort on-screen privacy
shielding, a keyboard command palette, and a small timetable assistant without
telemetry, remote academic-data APIs, or backend services.

The current source is a WXT + TypeScript + Preact project. The generated
extension is the only artifact that should be loaded into a browser; the
repository root is source code and is not itself an unpacked extension.

## What is verified

- Attendance formulas and invalid-input policy are covered by unit tests.
- Attendance and timetable fixture parsers are covered by unit tests.
- Exact VTOP host matching, settings normalization, lifecycle coalescing,
  privacy interactions, and command-palette keyboard boundaries are covered by
  unit tests.
- Chromium and Firefox production bundles are generated by WXT locally.

No authenticated live VTOP session was available during this migration. The
actual portal table headers, route destinations, timetable semantics, login
markup, and AJAX behavior must still be smoke-tested by a VIT student before a
release. The privacy shield is visual, best-effort concealment; it is not a
confidentiality boundary against developer tools, accessibility inspection,
page scripts, or screenshots.

## Features

### Attendance planning

When a portal table exposes attended and conducted integer columns, the
extension adds a separate planning column and a local overview. It never
overwrites portal attendance values. The simulator operates on local numbers
and does not change the portal table.

The supported integer model is:

```text
A = attended units
C = conducted units
safe absences = floor((4A - 3C) / 3), when 4A >= 3C
recovery target = max(0, 3C - 4A)
aggregate = sum(A) / sum(C)
```

The adapter labels the unit as hours or classes when the actual header says so;
it does not infer a conversion. Unknown or impossible values are shown as no
data. Threshold decisions use integer comparisons rather than rounded display
percentages.

### Privacy shield

CGPA/GPA-labelled values and values in detected marks/grade columns can be
blurred and revealed with click, Enter, or Space. Values remain in the portal
DOM, and no academic text is logged or sent anywhere. This is a user-interface
privacy aid, not data protection.

### Command palette

`Ctrl+K` and `Cmd+K` open a Shadow DOM-isolated palette. It ignores editable
controls, supports search, Arrow Up/Down, Enter, Escape, focus restoration, and
an empty-result state. Portal navigation runs only when a matching same-origin
link is visibly present on the current page; it does not invent destinations.

### Timetable and login assistance

The timetable adapter highlights a reliably matched current-day row and copies
the row's non-empty portal-order entries into an isolated assistant card. It
does not fabricate times, rooms, course names, or active-class state. Login
assistance is limited to verified-looking field selectors, registration-number
capitalization, password-to-captcha focus, and a captcha tooltip. It does not
store, transmit, or submit credentials itself.

## Development setup

Requirements:

- Node.js `22.23.3` (see `.nvmrc`)
- npm 10 or newer

Install the locked dependencies:

```sh
npm ci
```

Start WXT development mode:

```sh
npm run dev
```

Run the offline-capable unit test command after dependencies are installed:

```sh
npm test
```

Other checks:

```sh
npm run typecheck
npm run lint
npm run format:check
npm run build                 # Chromium / chrome-mv3
npm run build:firefox        # Firefox / firefox-mv3
npm run validate              # all checks and both production builds
npm run package               # clean, validate, and create Chrome + Firefox ZIPs
```

`npm test` does not access VTOP or the network. It uses sanitized local DOM
fixtures. `npm ci` and the first dependency installation require the package
registry unless the npm cache is already populated.

GitHub Actions runs `npm run package` for pushes to `main` and pull requests.
Successful runs publish the Chrome and Firefox ZIPs as workflow artifacts.

## Reproducible Docker check

The Dockerfile pins the Node major line and runs the full validation flow:

```sh
docker build -t vtop-modern-check .
docker run --rm vtop-modern-check
```

## Load locally

Build first:

```sh
npm run build
npm run build:firefox
```

For Chrome, Brave, or Edge:

1. Open the browser's extensions page (`chrome://extensions/` or equivalent).
2. Enable Developer mode.
3. Choose **Load unpacked**.
4. Select `.output/chrome-mv3/`.

For Firefox:

1. Open `about:debugging#/runtime/this-firefox`.
2. Choose **Load Temporary Add-on…**.
3. Select `.output/firefox-mv3/manifest.json`.

## Release packages

Run the package workflow from a clean checkout:

```sh
npm ci
npm run package
```

The generated, versioned archives are written under `.output/`:

```text
.output/vtop-modern-extension-<package-version>-chrome.zip
.output/vtop-modern-extension-<package-version>-firefox.zip
```

Only those browser-specific archives should be uploaded. The `package` script
cleans WXT's generated output before validation, so an old MV2 directory or
stale archive cannot accidentally be distributed with the current release.

The extension matches only these VTOP hosts:

```text
vtopcc.vit.ac.in
vtop.vit.ac.in
vtop2.vit.ac.in
vtopbhopal.vit.ac.in
vtop.vitap.ac.in
```

## Architecture

```text
entrypoints/
├── content.ts              # one WXT content entry and lifecycle coordinator
└── popup/                  # Preact popup entrypoint and local token CSS
src/
├── core/dom/               # lifecycle and Shadow DOM helpers
├── core/routing/           # exact host and route detection
├── core/storage/           # normalized sync preferences and local summary
├── features/attendance/    # pure math, table parser, isolated UI
├── features/privacy/       # targeted shield and isolated dock
├── features/timetable/     # fixture-backed day/slot parser and card
├── features/command-palette/
├── features/auth/          # bounded login enhancement
├── features/theme/
├── styles/content.css      # only narrow page selectors required for masking
└── types/
tests/                      # pure and sanitized DOM behavior tests
```

The lifecycle coordinator owns one MutationObserver, filters extension-owned
mutations, coalesces parser work, and schedules visual mounting separately.
Feature adapters receive affected roots and remain independently testable.
Extension-owned cards, dialogs, simulator controls, and command UI use Shadow
DOM boundaries. Page-controlled values are assigned with `textContent` or DOM
node APIs, not interpolated into HTML.

## Privacy and permissions

The generated manifest requests `storage` and `activeTab`, plus host access for the
five configured VTOP domains. `activeTab` is used only by the popup to select the
summary for the active configured VTOP host. There is no background service,
remote font import, telemetry, analytics, academic-data fetch, or
web-accessible resource. Popup quick links navigate only after an explicit user
click. Settings and a host-scoped derived attendance summary are the only
persisted data; summaries are cleared when an authentication page is entered.
Passwords, cookies, registration numbers, and raw academic tables are not
stored.

## Limitations and next step

Live VTOP verification is still required for each campus host. In particular,
verify attendance units and column labels, timetable matrix structure, portal
navigation labels, login modal selectors, dynamic table replacement, and
Chrome/Firefox popup storage behavior. Any selector found to differ should be
updated in the typed adapter and fixture before release.

See [`AUDIT.md`](AUDIT.md) for the evidence-based pre-migration findings.
